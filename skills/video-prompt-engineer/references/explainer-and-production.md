# Explainer structure and production handoffs

## Choose a teaching beat, not a fixed advertising formula

For an explainer, define what the viewer should understand or be able to do afterward. A useful optional sequence is: concrete problem or question → visible explanation or demonstration → objection or reaction → next action. A short demonstration may need only a question and its answer. Preserve an approved script; do not force a sales CTA, presenter or extra shots into a scoped prompt repair.

Give each beat a visual job and a spoken job. Show the process or result that supports the explanation, rather than an unrelated impressive montage. A fictional illustration is not evidence of tool performance. If showing a sample alongside a roadmap, make the stages legible and label illustrative or untested results.

For dialogue, distinguish the questioner, explainer and listener's reaction. Keep a recurring cast, environment, palette and approved references where useful. Reactions should express comprehension or the next question, not merely provide random cutaways. Exact UI, captions, diagrams and brand typography can be prepared as separate editing assets; do not infer how a reference ad was made from its finished appearance.

## Coverage follows information

Plan only the views needed to communicate the action. A shared view can establish relationships, a detail can clarify the mechanism, and a reaction can show its consequence. These are functions, not a compulsory wide–medium–close sequence. A single continuous take may serve the brief better.

For each planned shot record: ID; teaching beat; visible action and its entry/exit phase; framing and camera behavior; focus target; required identity/product references; narration or dialogue; intended cut or transition. Distinguish an insert of the ongoing action from a cutaway elsewhere. For separate generations, repeat necessary context and carry approved references; a shot list is not an automatically executed generation batch.

## Keep production stages explicit

| Stage | Output / handoff | What it does not establish |
|---|---|---|
| Planning | Approved brief, script, beat/coverage plan, reference list | A finished video or a tool's ability to render it |
| Generation preparation | Per-shot prompts, reference inputs, separately documented supported settings | That a natural-language request is an actual API control |
| Media generation | Requested visual/audio assets and job/output identifiers if actually executed | That assets match the brief or cut together |
| Review | Observed defects, accepted takes and targeted revision notes | Success from prompt wording or a single attractive frame |
| Editing and finishing | Selected takes, narration/music, exact graphics, timing, colour and delivery assembly | That a planning/chat tool performed those operations itself |

Name the actual tool for each stage only when known. Verify current model/endpoint capabilities separately before claiming execution support. Unknown tools remain unassigned. Planning, orchestration, image generation, video generation, voice, avatar animation and editing are different roles even when a product supports several. A creator's curriculum graphic naming products is not integration documentation.

This skill writes prompts and plans; it does not execute these stages. If another workflow is authorized to execute, pass the artifacts and outstanding questions to it. Preserve the user's chosen audio route: supported native dialogue, separate voiceover, or intentional silence. Exact narration should remain a script, not be replaced with generated text in the image. Use consented voices and approved assets.

## Original, untested example

Brief: Explain why a sideways camera move differs from a pan, using an existing cup-and-pillar scene.

- Question: “Why does the pillar hide the cup differently?” Shared view establishes the cup, foreground pillar and camera relationship.
- Demonstration: Two separately planned comparisons. A pan rotates from a fixed camera position; a truck moves sideways, revealing a changing overlap. Keep the scene and intended light fixed. Do not infer precise camera calibration from generated output.
- Explanation: Narration names rotation versus translation. Add accurate labels in the edit if desired.
- Next action: Invite the learner to compare the overlap in their own shots, without claiming a guaranteed generator result.

Handoff: beat plan → two scoped prompts and approved reference inputs → generation by a separately authorized workflow → inspect viewpoint behavior across the takes → assemble the comparison with narration and labels. If the user requests only the truck clause, return that clause; do not expand it into this entire film.

## Evidence boundary

The patterns above are editorial proposals informed by observed public creative, not conversion research, a camera tutorial transcript, or verified model recipes. See [research sources](craft-sources.md). Do not import mastery deadlines, unsupported success percentages, discount claims, certificate recognition or unrestricted voice-cloning promises into course copy. Describe actual exercises, deliverables and review criteria instead.
